# 铁路大亨 · 下一站推测

一个小窗口程序：**后台读游戏画面，告诉你下一站最可能是什么**。
不点击、不抢前台、不动鼠标，游戏放在后台或被别的窗口挡住都能读。

双击安装包装一次（可以自己选装到哪），之后点桌面图标就能开，启动 1.25 秒。
窗口常驻屏幕右下角。

* 只想用：到 [Releases](https://github.com/ts471002/railway-tycoon-bot/releases) 下 `RailwayTycoon-Setup-*.exe`。
* 想要源码：clone 下来双击 `打包安装版.bat`，会自己出安装包（需要先建好 `.venv`，
  见下面「自己跑源码」）。

---

## 它读的是什么

游戏右侧面板每站都会给出两行：

```
未来3站将有食铺站数量最多          ← 提示：未来几站的相对多少
旅程剩余站点：15站
酒庄x5  食铺x5  商行x5             ← 底牌：剩下的路三种各还剩几个
```

第二行是硬约束，等于把答案的底牌亮出来了。程序把四件事合起来算：

1. **剩余构成**：剩下的路上 酒庄/食铺/商行 各还有几个；
2. **滚动提示**：每站的「未来 N 站某某最多 / 各类型各 1 个」不是只管当时那一站，
   走一站之后窗口往前挪一格，旧提示里还有 N-1 站在未来，仍然有效；
3. **不会连续三站相同**：`酒庄 酒庄 酒庄` 这种排列直接排除；
4. **每类最多 6 个**：一局里任何一种站点数量上限是 6，读出来 >6 一律算认错
   （`66→6`、`16→6`、`11→1` 自动纠正，纠不动就丢掉这一帧）。

四条一起把「所有合法排法」穷举出来，按剩下位置的合法排法数加权，
得到的就是真概率，不是拍脑袋的估计。

## 界面怎么读

```
下一站
商行                     66.7%
酒庄 ▁▁▁▁▁▁▁▁▁▁▁▁   0.0%
食铺 ▅▅▅▅▁▁▁▁▁▁▁▁  33.3%
商行 ████████▁▁▁▁  66.7%
很可能是【商行】，但别当 100% 用
─────────────────────────────
后续站点              往后 3 站
        第2站   第3站   第4站
酒庄      0%      0%      0%
食铺     33%     33%    100%
商行     67%     67%      0%
─────────────────────────────
第 13 站 · 剩余 3 站 · 酒庄x0 食铺x1 商行x2
提示 未来3站中商行最多（另 2 条旧提示仍生效）
本局开局 15 站 · 已走 12 站
```

* 上面那块是**下一站**，大字 = 概率最高的那种；
* 中间那块是**后面几站**：行是三种店铺，列是第 2/3/4 站，
  每列概率最大的那格会高亮；
* 最下面几行是这一局的账：第几站、剩余构成、提示、开局与已走站数。

## 只在数字变了才刷新

程序盯着右侧面板那块区域，但**只有「旅程剩余站点」的数字真的变了才刷新界面**。
画面怎么动、动画怎么闪，推测结果都不会跟着跳。

## 为什么现在读得快

一次读数从最初的 **8~9 秒** 压到 **0.5~0.7 秒**，靠的是三件事：

1. **抓屏不再等"新的一帧"**。WGC 只在窗口内容变化时才交出新帧，之前每次都
   死等新帧，游戏画面一静下来就卡 1~5 秒。现在直接拿缓存里最新的那帧，
   并且帧号没变就连图都不转。
2. **不把图吹大再识别**。RapidOCR 3.x 默认把短边放大到 736——600×220 的面板
   被拉成 2004×736（31 倍像素），单次识别 4~9 秒。现在检测按 640 宽跑，
   识别用的裁剪框仍从 2 倍放大图取，小字不会糊。
3. **只读面板那一块**，不再整屏识别兜底；识别模型按 CPU 核数开线程
   （默认线程数实测慢 2.6 倍），并关掉了对屏幕截图毫无意义的方向分类。

## 「重置」

**重置 = 这一局完了**。点它只做一件事：把本局的记录清空。
它**不会**把当前屏幕上剩下的几个数字当成新一局的开局（那多半是上一局的残局）。
清空之后程序盯着画面，等新一局真正开始的那一刻（连续两帧读到同一个数字，
且画面相对重置时变过），才把那一帧记成开局，从这里重新算。

开局之后，三种数量都只会比开局小；任何比开局大或者比上一帧大的读数，
都判定为 OCR 认错并自动纠正，不会把账搞乱。另外每类数量不可能超过 6，
读到 7 以上（含 11/22/66 这种重复位）同样按认错处理。

## 画面尺寸不对？先看显示缩放

如果程序说「画面 1280×720」，但你的显示器明明是 1920×1080 / 2560×1440，
那不是程序算错了，是 **Windows 的显示缩放**在骗它：

- 缩放 150% 的 1920×1080 → 程序看到 1280×720
- 缩放 200% 的 2560×1440 → 也是 1280×720

没声明 DPI 感知的程序，系统会把窗口尺寸按缩放比例**虚拟化**，抓到的画面
还会被压/裁一截——右上面板正好被切掉，所以怎么校准都没用（校准用的是同一张错图）。

**新版已经声明了 Per-Monitor V2 DPI 感知，正常情况下不会再有这个问题。**
判断方法：界面底部如果出现「⚠ 画面尺寸对不上：窗口 1920×1080，抓到 1280×720」，
说明这个保护被触发了，按提示把「设置 → 系统 → 显示 → 缩放」改成 100% 再启动，
或者把游戏改成窗口化 1920×1080（窗口模式不吃缩放，一样能用）。

自检里也会把环境一起写出来，方便对照：

```
系统环境：DPI 感知 per-monitor-v2 · 缩放 1.50× · 主屏 1920×1080
窗口客户区 1920×1080  抓到 1920×1080  一致
```

## 换分辨率 / 换电脑读不到怎么办

**已经自动处理了，多数情况不用管。** 但知道原理能少踩坑：

面板的读取位置是在 1600×900 的窗口下量出来的。原来的做法是**按比例换算**，
看着很合理，实际上有个前提——游戏 UI 也跟着窗口等比缩放。可游戏（Unreal 的 UMG）
不一定这么干：窗口变大时，UI 元素可能只调位置不调大小，或者按高度缩放。
一旦不是等比，按比例算出来的框就整块落空，画面明明在，程序却说「没读到」。

所以现在改成会自己找，一共四级：

| 级别 | 做法 | 耗时 |
|---|---|---|
| 1 | 读上次学到的位置（第一次读到时自动记下来的，或手动校准的） | 0.5~0.7 秒 |
| 2 | 读 1600×900 下的标准位置 | 0.5~0.7 秒 |
| 3 | 在画面上按左右三条竖带各扫一遍，找到就**把真实位置记下来** | 首次 3~6 秒，之后永远走第 1 级 |
| 4 | **整屏切成 3×2 块**挨个认，面板藏在哪儿都能翻出来 | 首次 5~7 秒，之后永远走第 1 级 |

扫的是「竖条」不是「大横框」，因为识别模型会把长边压到 640——横着拉宽字会变小，
竖着拉高字一点不变。竖条宽度按画面宽度取 42%（以前写死 700 像素，
小窗口里字会被压到 13px 认不出来），所以 1280 / 1920 / 2560 / 4K 都是同样的效果。

第 4 级是给「面板不在右半边」的怪布局准备的（超宽屏、HUD 缩放、窗口被拖成长条）。
它比前三层贵，所以只在连续失败几次、并且隔 15 秒以上才跑一次。

**还找不到就别猜了，点界面上的「校准」**：会弹出一张当前画面的定格图，
按住左键框住右侧那一整块（「未来3站…」和「旅程剩余站点：…」都要在里面），
松手当场就会在那个框里识别一次，认到的字直接显示出来——认对了点「就用这个位置」。
框一次，以后一直用；换分辨率也能用，因为存的是比例。

记下来的位置存在 `data\panel_box.json`，是**比例**不是像素，换分辨率也能用。
判错了想重来：**双击界面右上角那个状态点**（「● 在线」），它会忘掉记住的位置重新找。

**点「诊断」** 会把这一帧画面、程序正在读的那块区域、识别到的原文一起存到
`logs\diag_时间\` 并自动打开文件夹。实在读不到就把这个文件夹发过来，
里面能直接看出是「区域偏了」还是「识别引擎本身没跑起来」。


真的怀疑读偏了，跑一次自检：

```bat
"铁路大亨推测.exe" --selftest
```

它会把画面认一遍，写到 `logs\selftest.txt`，里面有三样关键信息：

* **画面多大**（`画面 1920x1080`）
* **在读哪一块**（`读的区域 (1200, 36, 1920, 300)`）
* **位置哪来的**（`已对齐` / `标准位置`）

同时会把读的那一块单独存成 `logs\selftest_panel.png`——打开看一眼就知道
是区域偏了，还是那个界面本来就没有面板。远程排查把这两个文件发回来就够。

## 两个版本，按场景挑

| | 安装版 ★ | 文件夹版 |
|---|---|---|
| 文件 | `dist\铁路大亨推测-安装版.exe` | `dist\铁路大亨推测-快速版\` |
| 体积 | **92MB**（一个文件） | 232MB（一个文件夹） |
| 启动 | **1.25 秒** | 1.25 秒 |
| 怎么用 | 装一次，以后点桌面图标 | 双击里面的 exe |
| 适合 | 自己用 + 发给别人 | 改代码调试、或者不想装 |

**只发安装版**：它就是一个 exe，能单独发给别人；双击后可以自己选装到哪个盘哪个文件夹，
装完自动建桌面和开始菜单图标，之后每次启动 1.25 秒。装一次的钱（约 20 秒）只花一次。

两个版本跑的是同一份程序，读数都是 0.5 秒级别。文件夹版是安装版的原料——
安装版的构建流程就是「先出文件夹版，再压成 payload.tar.xz 塞进 exe」，所以两者永远同步。

## 为什么有这么大

这不是代码写得臃肿，是「离线中文 OCR」本身的成本。打进程序的是这些：

| 组成 | 未压缩 | 干什么用的 |
|---|---|---|
| OpenCV `cv2.pyd` | 74MB | 图像缩放、透视校正、算文字框的外接矩形 |
| onnxruntime | 48MB | 跑识别模型的计算引擎 |
| numpy | 34MB | 矩阵运算 |
| OCR 模型 PP-OCRv6 | 31MB | 检测 + 识别两个神经网络 |
| Python + Tk + 其余 | ~20MB | 运行环境 |
| 合计 | ~207MB | → 压成安装版 92MB |

下面三块砍不动，也是体积下不来的全部原因：

* **OpenCV 是一个整体**：74MB 全在一个 dll 里，不是按需加载的。这个项目只用到其中
  12 个函数（缩放、变色、透视变换、找轮廓），但用了 12 个也得把 74MB 整个带上。
  （已经换成 4.10 版，比 5.0 版小 9MB；砍掉它里面 26MB 的 ffmpeg 视频解码。）
* **onnxruntime 和模型是一对**：没有它就没人跑模型；不跑模型就只能联网调接口，
  那要联网、要 API key、截图还得传出去，不如现在这样。
* **模型已是官方最小档**：det 9.9MB + rec 21.2MB。试过量化成 int8（能到 8MB），
  但同一帧上识别结果和原模型对不上，没有可信样本验证之前不敢换——
  之前「1 读成 11」的账还没算清，不能在这上面赌。

真还想再小，只有「不要本地 OCR」这一条路，代价是必须联网，不划算。

**两个可能踩的坑：**

* **杀毒软件误报**。PyInstaller 打出来的、没签名的 exe 很容易被 Defender/360 当成
  可疑程序。原理是它确实会「解压自己再执行」，行为跟某些恶意软件像。加个信任就行，
  介意的话把源码（整个 `railway-tycoon-bot` 文件夹）发给对方，用 `.bat` 跑。
* **对方系统太老**。要求 Windows 10 1809 以上（后台抓屏用的 WGC 接口从这版才有）。

两个版本都在程序同目录建 `data\`、`logs\`，拷到别处数据跟着走；放在没写权限的目录
（比如 `C:\Program Files`）会自动改用 `%LOCALAPPDATA%\铁路大亨推测`。

安装版装在哪由你选，默认 `%LOCALAPPDATA%\铁路大亨推测`。想卸载就直接删掉那个文件夹，
再删桌面和开始菜单的快捷方式；或者重装一遍覆盖。

自己改了代码想重新出包：双击 `打包安装版.bat`（一步出成品）。
只想快速跑一下看效果，双击 `铁路大亨推测.bat` 直接以源码启动，不用打包。

## 文件

```
dist/铁路大亨推测-安装版.exe        安装版（打包产物，不进 git；双击 bat 生成）
dist/铁路大亨推测-快速版/           文件夹版（安装版的原料，也能直接双击里面的 exe）
installer.py                         安装器（选路径、解压、建快捷方式）
launcher.py                          程序入口（exe 和源码都从这里进，带 --selftest 自检）
铁路大亨推测-安装版.spec             安装版打包配置
铁路大亨推测-快速版.spec             文件夹版打包配置
打包安装版.bat                       一键出安装版（三步全自动）
打包快速版.bat                       只出文件夹版
tools/make_payload.py                把文件夹版压成 payload.tar.xz
铁路大亨推测.bat                     源码方式启动（改代码时用）
tools/next_station_gui.py            界面（后台抓屏 + 刷新策略）
tools/next_station.py                读屏、OCR、解析、纠错、记账、区域比例换算
tools/panel_calib.py                 手动校准窗口（框一次，固定读取区域）
tools/panel_regression.py            回归测试（6 种分辨率/摆位的合成面板）
bot/dpi.py                           声明 DPI 感知（显示缩放必须）
bot/journey.py                       求解器：剩余多重集 + 滚动提示 + 禁三连
bot/bgcapture.py                     WGC 后台抓屏
bot/ocr.py                           OCR 后端（RapidOCR）
bot/paths.py                         数据目录（源码=项目根，exe=exe 所在目录）
assets/sample_frame.png              回归测试用的一张游戏截图
data/journey_state.json              本局记录（本地状态，不进 git）
data/journey_archive/                每局结束时的存档
```

`.venv/`、`build*/`、`dist/`、`payload.tar.xz`、`data/`、`logs/` 都在 `.gitignore` 里，
仓库只放源码。

## 调试

```bat
.venv\Scripts\python.exe tools\next_station.py        :: 读一次，打印结论
.venv\Scripts\python.exe tools\next_station.py dump   :: 打印画面里所有 OCR 文字
.venv\Scripts\python.exe tools\panel_regression.py    :: 回归测试：6 种分辨率/摆位都要读到
铁路大亨推测.exe --selftest                            :: exe 自检，写 logs\selftest.txt
```

认错数字时先跑 `dump`，看看 OCR 到底读到了什么。
改了读屏逻辑就跑一遍 `panel_regression.py`，防止在某种分辨率上悄悄失效。

## 自己跑源码（开发环境）

```bat
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
铁路大亨推测.bat          :: 以源码启动界面
打包安装版.bat            :: 出 dist\铁路大亨推测-安装版.exe
```

要求 Python 3.11+、Windows 10 1809+（后台抓屏用的 WGC 接口从这版才有）。
