# 铁路大亨 · 下一站推测

![release](https://img.shields.io/github/v/release/ts471002/railway-tycoon-bot?color=%232a5d43)
![downloads](https://img.shields.io/github/downloads/ts471002/railway-tycoon-bot/total)
![platform](https://img.shields.io/badge/platform-Windows%2010%2B-2b6cb0)

游戏每站都会告诉你「旅程还剩几站、酒庄/食铺/商行各还剩几个」——底牌都亮给你了，
**但下一站是哪一个，还是要自己赌**。

这个小窗口在后台把这些数字读下来，把剩下的所有合法排法穷举一遍，直接告诉你三种店各占多少概率。

它不点击、不抢前台、不动鼠标，游戏放在后台、被别的窗口挡着都照读。

> **下载**：[Releases](https://github.com/ts471002/railway-tycoon-bot/releases/latest) · Windows 10 1809 以上 · 92MB · 启动约 1.25 秒

## 装上，然后忘掉它

1. 到 [Releases](https://github.com/ts471002/railway-tycoon-bot/releases/latest) 下载 `RailwayTycoon-Setup-*.exe`
2. 双击，选装到哪个文件夹（默认 `%LOCALAPPDATA%\铁路大亨推测`），装完桌面会出现图标，第一次约 20 秒
3. 打开游戏，停在能看到右侧面板的界面（大地图、进站选择都行），再双击桌面图标

窗口会待在屏幕右下角，不用管它。走到下一站、数字一变，它自己跟着更新。

第一次启动可能要 3~7 秒——它在找面板到底画在屏幕哪个位置，找到就记住，
以后每次读数 0.5~0.7 秒。

**不想要了**：停掉程序，删掉安装文件夹，再删桌面图标。没有注册表残留。

## 界面怎么看

```
下一站
商行                     66.7%
酒庄 ▁▁▁▁▁▁▁▁▁▁▁▁   0.0%
食铺 ▅▅▅▅▁▁▁▁▁▁▁▁  33.3%
商行 ████████▁▁▁▁  66.7%
很可能是【商行】，但别当 100% 用
─────────────────────────────
后续站点              往后 3 站
        第2站   第3站   第4站
酒庄      0%      0%      0%
食铺     33%     33%    100%
商行     67%     67%      0%
─────────────────────────────
第 13 站 · 剩余 3 站 · 酒庄x0 食铺x1 商行x2
提示 未来3站中商行最多（另 2 条旧提示仍生效）
本局开局 15 站 · 已走 12 站
```

| 位置 | 是什么 |
|---|---|
| 最上面的大字 | 下一站最可能是哪种，后面是它的概率 |
| 往下一段 | **再往后几站**：行是三种店，列是第 2/3/4 站，每列概率最大的会高亮 |
| 分隔线以下 | 这一局的账：第几站、还剩什么、当前提示、开局多少站、已走多少站 |

数字只会在这个面板真的变了的时候刷新。画面里动画怎么闪、车怎么跑，结果都不会跟着乱跳。

## 它凭什么算得准

因为这不是猜，是**穷举**。程序把四条规则同时套上去：

1. **剩余构成**——「酒庄x0 食铺x1 商行x2」意思是剩下的路上就这 3 个，一个不多一个不少；
2. **滚动提示**——每站的「未来 N 站里某某最多」不是只管当时那一站。走一站，窗口往前挪一格，
   旧提示里还有 N-1 站在未来，照样算数，所以越走越准；
3. **不会连续三站相同**——`酒庄 酒庄 酒庄` 这种排法直接排除；
4. **每类最多 6 个**——一局里任何一种站点上限是 6，读到 7 以上必定是认错了。

把所有满足这四条的排列列出来，按「每个位置有多少种合法走法」加权，得到的就是真概率。

所以它给你的 66.7% 是「三种走法里两种是商行」这种硬账，不是拍脑袋。

顺带一提：读数也是同样的思路。剩余构成只会变小、不会变大，所以读到比上一帧大的数
就当场判为识别错误并修正（`66→6`、`16→6` 这类重复位也能纠），纠不回来就丢掉这一帧，
宁可慢一拍也不写错账。

## 常见问题

### 一直显示「没读到」，游戏明明开着

先看两件事：**游戏窗口是不是最小化了**（最小化后 Windows 不再渲染，抓不到画面），
以及**当前界面有没有那块「旅程剩余站点」面板**（商店、设置、加载界面都没有）。

如果画面正常还是读不到，说明面板位置和程序预设的对不上。它会自己找（几秒到十几秒），
还找不到就点界面上的 **「校准」**：

> 弹出一张当前画面的定格图 → 按住左键框住右侧那一整块（「未来3站…」和「旅程剩余站点：…」都要在里面）
> → 松手，程序当场在框里识别一次 → 认到的字直接显示出来，认对了点「就用这个位置」。

框一次，以后一直用。存的是**比例**不是像素，换分辨率也有效。

想反悔：**双击界面右上角那个状态点**（显示「● 在线」的那个小圆点），它会忘掉记住的位置重新找。

### 显示的画面尺寸不对（比如 1920×1080 的屏显示成 1280×720）

这是 Windows **显示缩放**造成的：缩放 150% 时，系统会把 1920×1080 报成 1280×720。
新版已经声明了 DPI 感知，正常情况下不会再出现。

如果界面底部仍然出现「⚠ 画面尺寸对不上：窗口 1920×1080，抓到 1280×720」，
把「设置 → 系统 → 显示 → 缩放」改成 100% 再启动；或者把游戏设成**窗口化 1920×1080**
（窗口模式不吃系统缩放）。

### 概率能当准数用吗

能当参考，别当保证。66.7% 是「三种走法里两种是商行」，这个比例本身是精确的；
但它建立在**读数正确**和**规则完整**之上——游戏如果有额外规则（比如某种店有前置条件），
程序不知道。它给的是「在不违反已知规则的所有可能里，哪一种占多少」。

### 「重置」到底重置什么

**重置 = 这一局结束了**。它只做一件事：把本局的账清空。

它不会把当前屏幕上剩下的数字当成新一局的开局（那多半是上一局的残局）。清空之后程序盯着画面，
等新一局真正开始的那一刻，才把那一帧记成开局，从这里重新算。

### 杀毒软件报警

大概率是误报。PyInstaller 打包的、没有代码签名的 exe 经常被 Defender / 360 盯上，
因为它的行为和某些恶意软件确实像——自解压、释放文件、再执行。加个信任就行。

不放心的话，下载源码自己看，或者自己打包（见最后「给开发者」）。

### 它会帮我点吗

不会，也不打算做。它只读屏幕，不改游戏、不模拟按键、不联网。
你看到的是概率，做决定的还是你。

## 为什么有 92MB

不是代码臃肿，是「**离线**中文识别」本身的成本——正因为模型在本地跑，
它才不需要联网、不需要 API key、不会把你的截图传到任何地方。

| 组成 | 未压缩 | 干什么用的 |
|---|---|---|
| OpenCV | 74MB | 图像缩放、透视校正、找文字框 |
| onnxruntime | 48MB | 跑神经网络的计算引擎 |
| numpy | 34MB | 矩阵运算 |
| OCR 模型 | 31MB | 检测 + 识别两个网络 |
| Python + Tk + 其余 | ~20MB | 运行环境 |
| 合计 | ~207MB | → 压成安装版 92MB |

这三块都砍不动：OpenCV 74MB 全在一个 dll 里，不是按需加载（这个项目只用到其中十几个函数，
但也得整个带上）；onnxruntime 和模型是一对，去掉就只能联网识别；模型已经是官方最小档，
试过压到 int8（能省 23MB），但同一帧上识别结果和原模型对不上，没有可信样本验证之前不换。

<summary>构建、调试、项目结构（点开）</summary>

**环境**：Python 3.11+、Windows 10 1809+（后台抓屏用的 WGC 接口从这版才有）。

```bat
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
铁路大亨推测.bat          :: 以源码启动界面，改完直接看效果
打包安装版.bat            :: 出 dist\铁路大亨推测-安装版.exe
```

**调试**：

```bat
.venv\Scripts\python.exe tools\next_station.py        :: 读一次，打印结论
.venv\Scripts\python.exe tools\next_station.py dump   :: 打印画面里所有 OCR 文字
.venv\Scripts\python.exe tools\panel_regression.py    :: 回归测试：6 种分辨率/摆位都要读到
铁路大亨推测.exe --selftest                            :: 自检，写 logs\selftest.txt
```

认错数字先跑 `dump` 看 OCR 到底读到了什么。改了读屏逻辑一定要跑 `panel_regression.py`——
1280×720 下字形被压小、面板贴在左边，这两个坑本机是复现不出来的，全靠它拦。

**两个版本**：安装版（92MB 单文件，启动 1.25 秒）是最终产物；文件夹版（232MB 目录）
是它的原料，打包流程就是「先出文件夹版 → 压成 payload.tar.xz → 塞进 exe」，所以两者永远同步。
单文件版（onefile，启动 6.5 秒）已经不再维护。

**结构**：

```
installer.py                 安装器：选路径、解压 payload、建快捷方式
launcher.py                  入口（exe 和源码都从这里进，带 --selftest）
铁路大亨推测-安装版.spec      安装版打包配置
铁路大亨推测-快速版.spec      文件夹版打包配置
打包安装版.bat                一键出安装版（三步全自动）
tools/make_payload.py         把文件夹版压成 payload.tar.xz
tools/next_station.py         读屏、OCR、解析、纠错、记账、区域定位
tools/next_station_gui.py     界面（抓屏循环 + 刷新策略）
tools/panel_calib.py          手动校准窗口
tools/panel_regression.py     回归测试
bot/bgcapture.py              WGC 后台抓屏
bot/ocr.py                    OCR 后端（RapidOCR）
bot/journey.py                求解器：剩余多重集 + 滚动提示 + 禁三连
bot/dpi.py                    声明 Per-Monitor V2 DPI 感知
bot/paths.py                  数据目录（源码=项目根，exe=exe 同目录）
assets/sample_frame.png       回归测试用的游戏截图
```

**面板定位是四级降级**，因为在别的机器上「面板在哪」不可控（Unreal 的 UMG 可能只调位置
不调大小，HDR 缩放、超宽屏、窗口拖成长条都会让比例换算失效）：

| 级别 | 做法 | 耗时 |
|---|---|---|
| 1 | 上次学到的位置（比例，存 `data\panel_box.json`） | 0.5~0.7 秒 |
| 2 | 1600×900 基准位置 | 0.5~0.7 秒 |
| 3 | 三条竖带扫描（宽 42%，竖条不改字高） | 3~6 秒 |
| 4 | 全屏 3×2 分块 | 5~7 秒 |

第 3、4 级只在连续失败后才跑，且带退避（4→12→36→60 秒封顶），避免停在商店界面时白烧 CPU。

`.venv/`、`build*/`、`dist/`、`payload.tar.xz`、`data/`、`logs/` 都在 `.gitignore` 里，仓库只放源码。
